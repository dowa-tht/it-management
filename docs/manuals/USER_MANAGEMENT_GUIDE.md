# 👤 คู่มือการจัดการผู้ใช้และความปลอดภัย (User Management Guide)

คู่มือนี้รวบรวมขั้นตอนการทำงานและมาตรฐานความปลอดภัยสำหรับการจัดการบัญชีผู้ใช้ในระบบ DOWA IT ตั้งแต่การสร้างบัญชีใหม่ไปจนถึงการตรวจสอบสิทธิ์การเข้าใช้งาน

---

## 1. ช่องทางการเพิ่มผู้ใช้ (User Creation Paths)

ระบบแบ่งประเภทการเพิ่มผู้ใช้ตามวัตถุประสงค์การใช้งาน ดังนี้:

### 1.1 Account Management (แผงควบคุมหลัก)
**หน้าจอ:** `Settings > Users`
**วัตถุประสงค์:** สำหรับพนักงานประจำเป็นหลัก (IT, Supervisor, Manager)
- **Invite Path (แนะนำ):** Admin กรอกชื่อและอีเมล ระบบจะส่งอีเมลเชิญเพื่อให้ผู้ใช้ตั้งรหัสผ่านและ PIN เอง (Self-Registration) เพื่อความเป็นส่วนตัวสูงสุด
- **Manual Path:** Admin ตั้งรหัสผ่านเริ่มต้นให้ ระบบจะบังคับให้ผู้ใช้เปลี่ยนรหัสผ่านทันทีเมื่อเข้าใช้งานครั้งแรก (Enforced Change)

### 1.2 Quick Add (การเพิ่มผู้แจ้งแบบด่วน)
**หน้าจอ:** `Incidents > New`
**วัตถุประสงค์:** สำหรับเพิ่มชื่อพนักงานหน้างานหรือบุคคลภายนอกเพื่อให้ระบุตัวตนในเอกสารและเซ็นชื่อได้ทันที
- **OTP-Only Mode:** ผู้ใช้ที่เพิ่มผ่านช่องทางนี้จะยังไม่มีรหัส PIN ระบบจะส่ง **Email OTP** ให้ทุกครั้งที่มีการเซ็นชื่อ จนกว่าจะทำ Onboarding เสร็จสิ้น

---

## 2. ขั้นตอนการเริ่มใช้งาน (Mandatory Onboarding Flow)

ผู้ใช้ใหม่ทุกคน "ต้อง" ผ่านการทัวร์ระบบและตั้งค่าความปลอดภัยก่อนเข้าถึง Dashboard:

1.  **Welcome & Identity Check:** ยืนยันตัวตนผ่าน Token ที่ส่งทางอีเมล
2.  **Password Standard:** บังคับตั้งรหัสผ่านใหม่ที่มีความปลอดภัยสูง:
    - ขั้นต่ำ 8 ตัวอักษร
    - ต้องมี: ตัวพิมพ์ใหญ่ (A), ตัวพิมพ์เล็ก (a), ตัวเลข (0-9) และอักขระพิเศษ (@#$)
3.  **Signature PIN Setup:** บังคับตั้งรหัส PIN 6 หลัก (ตัวเลข) สำหรับใช้ลงนามในเอกสารอิเล็กทรอนิกส์
4.  **SSO Link (Optional):** เชื่อมต่อกับ Microsoft Account (Azure AD) เพื่อความสะดวกในการ Login ครั้งต่อไป

## 3. สถาปัตยกรรมความปลอดภัย (Security Architecture)

ระบบใช้มาตรฐาน **Zero-Trust** และ **Double-Lock** เพื่อป้องกันการเข้าถึงโดยไม่ได้รับอนุญาต:

### 3.1 Double-Lock Whitelist
แม้ผู้ใช้จะ Login ผ่าน Supabase Auth สำเร็จ แต่ระบบจะเช็ค "ทะเบียนขาว" (Whitelist) ทันที:
- ระบบเก็บค่า SHA-256 Hash ของอีเมลไว้ในตาราง `user_whitelist`
- หากอีเมลที่ Login เข้ามาไม่มีใน Whitelist ระบบจะ **Sign Out ทันที** และดีดไปหน้า Access Denied

### 3.2 Gatekeeper Guard
- **Server Proxy:** ดักจับการเข้าถึงโฟลเดอร์ `/dashboard` ทั้งหมด
- **Onboarding Check:** ตรวจสอบสถานะ `is_onboarded` หากยังไม่สำเร็จ จะถูก Redirect ไปที่หน้า Onboarding พร้อม Token ใหม่เสมอ

---

## 4. มาตรฐานการยืนยันตัวตนการลงนาม (Signature Standards)

| สถานะผู้ใช้ | วิธีการยืนยันตัวตน | มาตรฐานความปลอดภัย |
| :--- | :--- | :--- |
| **Onboarded** | **Signature PIN 6 หลัก** | Hash ด้วย Bcrypt (IT ไม่ทราบรหัส) |
| **Quick Add / Guest** | **Email OTP 6 หลัก** | อายุ 30 นาที, ล็อคหลังผิด 5 ครั้ง |

---

## 5. การกู้คืนบัญชี (Account Recovery)

- **Forgotten Password:** ผู้ใช้สามารถกด "Forgot Password" หน้า Login เพื่อขอรหัส OTP ทางอีเมลและตั้งรหัสผ่านใหม่ได้เอง
- **PIN Reset:** หากลืม PIN หรือ PIN ถูกล็อค ต้องติดต่อ IT Admin เพื่อทำการ `Unlock` หรือ `Reset PIN` ให้ใหม่ผ่านหน้า Settings เท่านั้น
