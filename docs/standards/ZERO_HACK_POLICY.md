# Zero-Hack Policy & Data Integrity

เพื่อให้ระบบมีความน่าเชื่อถือและตรวจสอบได้ (Audit-Ready) การพัฒนาระบบและ AI Agent ต้องปฏิบัติตามนโยบาย **"Zero-Hack Policy"** อย่างเคร่งครัด:

1.  **Strict Standard Only (ยึดมาตรฐานเป็นหลัก):** การกำหนดสถานะ (Status) หรือบทบาท (Role) ต้องเป็นไปตามที่ระบุในมาตรฐาน `DOCUMENT_STATUS_STANDARD.md` หรือเอกสารโครงสร้างหลักเท่านั้น
2.  **No UI Hacks (ห้ามเขียนโค้ดแก้ขัด):** ห้ามเขียน Logic ฝั่ง Frontend (UI) หรือ Backend เพื่อดัดแปลงค่าที่ผิดมาตรฐานให้แสดงผลดูเหมือนถูกต้อง (เช่น การใช้ `status === 'Resolved' ? 'Closed' : status` หรือเงื่อนไข `If...Else` เพื่อซ่อนความผิดพลาดของข้อมูล)
3.  **Transparent Error (แสดงผลตามจริง):** หากข้อมูลใน Database ผิดพลาดหรือไม่ตรงมาตรฐาน ระบบต้องดึงค่าที่ผิดนั้นมาแสดงผลตรงๆ เพื่อให้ผู้พัฒนาหรือ Admin เห็นความผิดปกติและรับรู้ปัญหาที่แท้จริง
4.  **Migration-First Approach (แก้ที่ต้นทางเสมอ):** หากต้องการเปลี่ยนมาตรฐาน (เช่น เปลี่ยนชื่อจาก Resolved เป็น Closed) ห้ามใช้การแก้ขัดด้วยโค้ดโดยเด็ดขาด แต่ต้องทำการ **Data Migration** อัปเดตข้อมูลในฐานข้อมูลทั้งหมดให้ถูกต้องตรงตามมาตรฐานใหม่เท่านั้น
