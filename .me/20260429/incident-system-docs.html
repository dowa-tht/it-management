Open Incidents

นับจำนวน Incident ที่ยังเปิดอยู่ แสดงเป็น Stat Card สีแดง พร้อม Link ไปหน้า Incident List ที่ filter status=open

✅

Resolved Today

นับ Incident ที่ปิดในวันนี้ แสดงสีเขียว เป็นตัวชี้วัดประสิทธิภาพรายวัน

📊

SLA Compliance Rate

เปอร์เซ็นต์ Incident ที่ resolve ทันกำหนด SLA เทียบกับ Target (ปกติ 95%) แสดงเป็น Gauge Chart

โมดูลการทำงาน
📋

Dashboard Module

แสดงสรุปภาพรวมระบบ ประกอบด้วย Stat Cards (KPI), SLA Gauge Chart, รายการ Incident ล่าสุด 5 รายการ และ Quick-Action Buttons เช่น "สร้าง Incident" และ "Import วันหยุด" — อัปเดตอัตโนมัติทุกครั้งที่มีการเปลี่ยนแปลงข้อมูล

⚙️

Master Data / Settings

จัดการข้อมูลตั้งต้นของระบบ ได้แก่ Working Hours (วันและเวลาทำงาน), Holidays (วันหยุดนักขัตฤกษ์), Incident Categories และ Checklist Templates — รองรับการ Import วันหยุดจาก CSV

🗂️

Incident Management

สร้าง แก้ไข และติดตาม Incident แต่ละรายการ ระบบจะออก Case Number อัตโนมัติ กำหนด Severity (High/Medium/Low) และ Status (Open → InProgress → Resolved → Closed) พร้อมระบุผู้รายงานและผู้รับผิดชอบ

⏱️

SLA Engine

คำนวณ SLA Deadline โดยนับเฉพาะเวลาทำงานจริง (ไม่รวมวันหยุดและนอกเวลา) รองรับการ Pause/Resume SLA ด้วย Manual Exclusion และคำนวณ Compliance Rate อัตโนมัติ

✔️

Checklist System

รายการตรวจสอบแนบกับ Incident แต่ละรายการ แบ่งเป็น Daily / Weekly / Monthly แต่ละรายการมี 3 สถานะ: Pending, Done, Skipped — เชื่อมโยงกับ KPI บน Dashboard

🔔

Notification System (Optional)

Scheduler รันทุก 5 นาที ตรวจสอบ Incident ที่ใกล้หมด SLA (เหลือ <10% ของเวลาที่กำหนด) แล้วส่ง Alert Toast แจ้งผู้ใช้งานแบบ Real-time

ฟีเจอร์ Holiday Import CSV

📥 นำเข้าวันหยุดจาก CSV

ระบบรองรับการ Import วันหยุดแบบ Bulk ผ่านไฟล์ CSV รูปแบบ UTF-8 (รองรับภาษาไทย)

รูปแบบ CSV:
คอลัมน์ที่ 1 : Date (dd/mm/yyyy)
คอลัมน์ที่ 2 : ชื่อวันหยุดภาษาไทย
คอลัมน์ที่ 3 : ชื่อวันหยุดภาษาอังกฤษ

ตัวอย่าง: 01/01/2567, วันขึ้นปีใหม่, New Year's Day
การไหลของข้อมูลในระบบ (13 ขั้นตอนหลัก)
01

เปิด Dashboard

ผู้ใช้เปิดหน้า Dashboard → ShowDashboard() เรียก Service Layer ดึง KPI Stat Cards, SLA Gauge (Compliance Rate vs Target), Incident ล่าสุด 5 รายการ และ Quick-Action list → Render UI ทั้งหมด

02

เข้าเมนู Master Data

OpenMasterData() แสดงแท็บย่อย: Working Hours, Holidays, Incident Categories, Checklist Templates

03

ตั้งค่าเวลาทำงาน

กรอก Start/End Time + วันทำงาน → UI_SaveWorkingHours() → Service_SaveWorkingHours() → DB_Upsert('system_settings') → Toast "บันทึกสำเร็จ" — ค่านี้ถูกใช้โดย SLA Engine ทุกครั้งที่คำนวณ

04–05

จัดการวันหยุด (Manual + CSV Import)

เพิ่ม/แก้ไข/ลบ วันหยุดทีละรายการ หรือ Import จาก CSV — แต่ละแถว CSV ถูกแปลงเป็น THoliday แล้วเรียก Service_AddHoliday() ซ้ำจนครบ → บันทึกลง DB ตาราง holidays

06

แสดงรายการ Incident

ShowIncidentList(Filter) รองรับ Filter หลายมิติ: Status (All/Open/InProgress/Resolved/Closed) และ Severity (All/High/Medium/Low) → ส่ง SQL แบบ dynamic ไป Query DB → แสดงตาราง

07

เปิด Incident Detail

OpenIncidentDetail(IncId) ดึงข้อมูล Incident + Exclusions (ประวัติ Pause SLA) + Checklist ทั้งหมดพร้อมกัน → แสดง Detail View พร้อม Timeline SLA และรายการ Checklist

08

แก้ไข Incident

ปรับ Status / มอบหมายผู้รับผิดชอบ / แก้ข้อมูล → UI_UpdateIncident() → Service_SaveIncident() → คำนวณ SLADeadline ใหม่ (SLA_CalcDeadline()) ทุกครั้งที่บันทึก → DB_Upsert

09

Pause SLA (Manual Exclusion)

เพิ่ม Exclusion ระบุเหตุผลและเวลาเริ่ม → UI_AddExclusion() → Service_AddExclusion() → เพิ่ม record ใน Exclusions array ของ Incident → คำนวณ Deadline ใหม่ (หักเวลา pause ออก) → บันทึกและ Refresh UI

10

Resume SLA

UI_ResumeSLA() → Service_ResumeSLA() → ปิด Exclusion ที่ยังเปิดอยู่ทั้งหมด (ตั้งค่า EndAt = Now) → คำนวณ Deadline ใหม่ → บันทึกและ Refresh UI

11

ทำ Checklist

ShowChecklist(IncId) → แสดงรายการ Daily/Weekly/Monthly → ผู้ใช้เปลี่ยน Status (Pending/Done/Skipped) → UI_UpdateChecklistItem() → Service_SaveChecklistItem() → Dashboard KPI อัปเดตอัตโนมัติ

12

Dashboard Auto-Refresh

ทุกครั้งที่ Incident หรือ Checklist เปลี่ยนแปลง → เรียก Service_GetStatCards() และ Service_GetSLAComplianceInfo() ใหม่ → อัปเดต UI แบบ Real-time

13

SLA Notification

Scheduler รันทุก 5 นาที → Service_CheckSLAThreshold() → ดึง Incident ที่ Status=Open → ตรวจสอบว่า SLADeadline - Now < 10% → ถ้าใช่ → Push Alert Toast ไปแสดงที่ UI

SLA Engine — การคำนวณและตรรกะ

ขั้นตอนคำนวณ SLA Deadline

Business Time ✓
slaStartAt (createdAt + 1min) slaDeadline
SLADeadline = slaStartAt + NetBusinessMinutes

NetBusinessMinutes = Σ(นาทีทำงานจริง)
   - ไม่นับ: วันหยุดสุดสัปดาห์ (ตาม WorkDays)
   - ไม่นับ: วันหยุดนักขัตฤกษ์ (holidays table)
   - ไม่นับ: ช่วงนอกเวลา (ก่อน startTime / หลัง endTime)
   - ไม่นับ: ช่วง Manual Exclusion (Pause SLA)
⏸️

Pause SLA (AddExclusion)

เมื่อเพิ่ม Exclusion ใหม่ → ระบบบันทึก startAt = now, endAt = null → คำนวณ Deadline ใหม่โดยหักช่วง Pause ออก → SLA Deadline จะ "ขยาย" ออกไปตามเวลาที่ Pause

▶️

Resume SLA

เมื่อ Resume → ปิด Exclusion ทั้งหมดที่ endAt = null โดยตั้ง endAt = now → คำนวณ Deadline ใหม่ → SLA นับต่อจากตรงนี้

📈

SLA Compliance Rate

คำนวณจาก Incident ที่ปิดแล้ว (Resolved/Closed) ที่ slaComplianceRate ≥ Target (95%) หารด้วยจำนวน Incident ที่ปิดทั้งหมด × 100

⚠️

SLA Alert Threshold

Scheduler ตรวจทุก 5 นาที: ถ้า SLADeadline - Now < 10% ของเวลาทั้งหมด → Push Alert ชื่อ Incident ให้ผู้ใช้รับทราบก่อนหมดเวลา
